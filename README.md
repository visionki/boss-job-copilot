# BOSS Job Copilot

**一个用于 BOSS 直聘求职的 Agent Skill。**

将简历、项目经历和求职偏好交给 Agent，从职业画像分析开始，制定搜索策略、审查岗位匹配度，并在确认后发送招呼。支持先预览再发送，也可以只用来分析职业定位。

推荐搭配 Codex 使用；其他支持 Skill、具备本地文件与命令执行能力的 Agent，也可以按各自的安装方式接入。

> **风险提醒**：本项目仅供学习与个人参考，与 BOSS 直聘无官方关联。自动化操作可能触发验证、限流或账号封禁，使用风险由使用者承担。Zendriver 不保证免风控；在适用法律允许的范围内，作者及贡献者不对相关损失承担责任。详见文末免责声明。

## 快速开始

### 环境要求

- 支持 Skill、能读写本地文件并执行命令的 AI Agent
- Python 3.11+、桌面 Chrome、BOSS 直聘账号
- 当前实机验证环境：Codex / Windows / Python 3.13 / Zendriver 0.16.0

**推荐模型：GPT-5.6 Luna，推理强度 Max。**

### 安装

以 Codex 为例，在一个求职工作目录中打开会话，发送：

```text
请从 https://github.com/visionki/boss-job-copilot 安装 Skill，
将仓库中的 skills/boss-job-copilot 安装到当前目录的
.agents/skills/boss-job-copilot。
```

也可以下载仓库，手动复制该文件夹。Codex 的安装路径见 [官方文档](https://learn.chatgpt.com/docs/build-skills)；安装后未显示时，新开会话或重启应用。其他 Agent 按其 Skill 安装位置配置，目前尚未逐一验证。

### 开始使用

附上简历、项目经历或其他职业背景材料即可。以下是 Codex 的调用示例，其他 Agent 使用对应的 Skill 调用方式：

```text
使用 $boss-job-copilot。
这是我的简历和过往项目经历，请帮我找工作，先分析职业背景并和我确认求职策略。
```

首次使用会引导准备运行环境，并尽早打开专用 Chrome 窗口、检查 BOSS 登录状态。你可以一边登录，一边看 Agent 分析简历和项目、整理职业画像与求职策略；方案确认后，登录正常就直接开始搜索。只做职业分析时无需打开浏览器。

只打开浏览器时默认显示空白页；需要进入 BOSS 可让 Agent 打开首页并检查。若手动关闭标签页后连接失效，可让 Agent 复用原登录资料重开专用窗口。关闭或重开不会清理岗位、审查或沟通记录，详见 [故障恢复](skills/boss-job-copilot/references/operations.md#暂停关闭与故障)。

## 使用流程

1. **分析职业画像**：结合简历、项目经历和补充交流，梳理优势、能力证据、可迁移经验及适合的岗位方向。项目材料可以是文字、作品链接或代码，不必只提供简历。
2. **确认求职策略**：讨论城市、薪资、公司偏好、职责方向，以及哪些条件必须满足、哪些可以放宽。职业画像、搜索方案和招呼参考稿一起展示，确认后开始搜索。
3. **用首批岗位校准**：收集列表、去重入库，再阅读完整职位描述。首批默认审查 10 个，展示匹配结果、判断理由和招呼全文，并对照原策略核对方向；有分歧就继续调整。
4. **授权后批量沟通**：确认后先处理首批，再按每组 20 个持续审查和发送合适岗位。可以调整每组数量、指定发送多少个就停，或继续处理本轮剩余岗位；实际发送受授权范围和平台限制约束。
5. **随时调整与接续**：过程中可以暂停、修改方向或调整话术。资料和处理进度保存在工作目录，下次会话可以继续。

首批没有合适且可联系的岗位时，会再补一组；遇到影响判断的新问题，也会先与你讨论。审查结果和待发送内容直接展示在聊天中。

## 使用建议

- **补充代表项目**：说明解决的问题、自己的职责、关键取舍和实际成果，有助于发现简历里没有充分表达的优势。
- **区分底线与偏好**：明确哪些条件不能接受，哪些可以沟通，减少误筛。
- **认真看首批结果**：重点看保留、排除的理由是否符合预期，校准后再继续批量处理。
- **给招呼一个参考风格**：可以提供喜欢的例句。默认把核心优势放在开头，再写相关经历和岗位匹配点，以邀请看简历或交流收尾。
- **不同方向使用不同目录**：分别保存策略和岗位库。BOSS 登录可能互相挤下线，建议复用专用浏览器窗口。

也支持单独使用某个环节，例如“只分析职业画像，暂时不找岗位”或“只打开专用浏览器，我自己使用”。

## 默认策略

| 项目 | 行为 |
| --- | --- |
| 收集范围 | 每个关键词、城市及筛选组合默认最多 10 页，可调整 |
| 审查方式 | 首批 10 个校准，后续每批默认取 20 个；Agent 阅读实际职责，整体匹配优先 |
| 条件核对 | 逐岗核对实际工作地点、薪资等已确认底线；职责边界按个人策略，不预设职业方向 |
| 薪资匹配 | 实际岗位薪资区间与目标有交集即可保留，含端点；另行遵守明确的薪资底线 |
| 招聘方活跃度 | 默认本周以内及未知可联系，明确过久的匹配岗位暂缓 |
| 操作频率 | 页面动作串行，至少间隔 5 秒；遇到验证或平台限制时停止 |
| 联系去重 | 已沟通岗位跳过；发送结果不确定时只核验，不自动重发 |
| 历史记录 | 重复采集保留已有审查和沟通记录，需要重审时可明确指定 |

## 实现方式

- **Zendriver + Chrome**：负责搜索、翻页、读取详情和消息操作，复用专用登录资料。
- **聊天界面兼容**：支持详情页聊天弹窗和完整聊天页，核对当前岗位、招聘方和发送结果。故障重启默认返回 BOSS 首页，关闭浏览器不改变岗位进度。
- **SQLite**：保存岗位、审查理由、招呼及沟通记录，按岗位 ID 去重。
- **统一取数入口**：`boss.py jobs --unreviewed --view review --limit 20` 返回待审列表及已有完整详情，保留工作地址等关键事实；不按职位关键词预选，判断交给 Agent。
- **AI Agent**：负责职业分析、策略讨论和岗位匹配判断，无需在脚本中另配 LLM API Key。

开发试用中，Codex 直接控制的 BOSS 标签页曾反复跳转到空白页，具体触发原因未确认。改用 [Zendriver](https://github.com/cdpdriver/zendriver) 后解决了当时试用环境的访问问题，因此采用这套浏览器方案。它不保证绕过风控，也不会自动破解验证码。

## 数据存储

资料与进度默认保存在当前工作目录的 `.boss-workspace/`，包含职业画像、求职策略、岗位数据库和浏览器登录资料。岗位结果可按需查询或导出报告；升级 Skill 时保留该目录即可。

请勿公开这个目录或未脱敏的运行日志。交给 Agent 的材料仍会按所用模型服务与账户设置处理，本地保存并不意味着模型离线运行。

## 开发与打包

Skill 位于 [`skills/boss-job-copilot`](skills/boss-job-copilot)，包含指引、模板、Python 脚本和测试。

```bash
python -m pip install -r skills/boss-job-copilot/scripts/requirements.txt
python -m unittest discover -s skills/boss-job-copilot/scripts/tests -v
python skills/boss-job-copilot/scripts/package_skill.py --out dist/boss-job-copilot.zip
```

设置 `BOSS_BROWSER_FIXTURE=1` 可启用需要本机 Chrome 的离线页面测试。分享包按公共文件白名单生成，包含可安装的 Skill 文件夹及 SHA256 清单。
